# 把桌宠升级成系统级 Harness：设计方案

> 状态：路线 A（自己演进）。**第 1–3 阶段已完成**（见 [AGENT.md](AGENT.md) 的“运行时内核”“系统级运行时”“技能、守则、权限规则、钩子”三节），第 4、5 阶段待做。
> 参考：DeepSeek Harness（`dsh`，2026-08 开源，MIT，开发者预览版）的官方仓库文档，以及 Claude Code 的机制。
> dsh 的权限 / 沙箱 / MCP / 技能相关页面没有读到，下文涉及这几块时标了“未核实”。

## 一句话目标

**她还是她**：同一个角色、同一套性格、同一份自我记忆、同一个桌面形象。
**变化在她身后**：把现在嵌在桌宠里的 Agent 抽出来，变成一个常驻的、可扩展的运行时（Harness）。
桌宠窗口、聊天窗口、远程网页，以后还可以加上命令行，都只是这个运行时的不同“前端”。

```
                ┌──────────── Harness Host（常驻，主进程内，开机自启）────────────┐
 桌宠窗口 ──┐   │  会话日志(事件溯源) ─ 回合循环 ─ 工具注册表 ─ 权限/规则 ─ 沙箱     │
 聊天窗口 ──┼─▶ │  模型适配器 ─ 钩子 ─ 斜杠命令 ─ 技能 ─ 指令文件 ─ 子智能体 ─ 定时任务 │
 远程网页 ──┤   │  人格插件（她是谁）  ·  形象插件（她怎么表现）                       │
 命令行 pet ┘   └──────────────────────────────────────────────────────────────────┘
          （都通过同一套本地 RPC 协议）
```

## 两个参考对象各学什么

| 来源 | 值得学的 | 不照搬的 |
| --- | --- | --- |
| **DeepSeek Harness** | “一切皆插件”：模型、工具、会话、循环都是可替换的接缝（seam），插件卸载时注册自动撤销；**事件溯源的会话日志**（模型能看到的 = 日志里有的），压缩只是“替换视图”，可以从回合边界分叉；**步骤/回合**的明确划分和生命周期事件（`agent/pre-step`、`tools/pre-execute`、`agent/turn-stopping`…）；工具通过 `isConcurrencySafe` 主动声明能否并行；**单调的权限守卫**（拒绝了就不能被后面的插件改回允许）；Electron 桌面端用一个私有 Host 承载运行时、窗口只做展示 | 直接依赖 Cordis 和 dsh 本体：它还是预览版，官方明说会有不兼容的改动；它面向写代码，Windows 桌面操作、权限分级、人格这些都要自己做 |
| **Claude Code** | 用户可配置的 **Hooks**（PreToolUse / PostToolUse / UserPromptSubmit / Stop / SessionStart，脚本通过 JSON 输入输出）；**权限模式 + 规则**（按工具和参数模式写 allow / deny / ask）；**分层指令文件**（全局 + 项目的 CLAUDE.md / AGENTS.md）；**技能**（SKILL.md，平时只给描述，用到才加载全文）；**子智能体**（独立上下文，只交回结论）；**斜杠命令**（/compact、/clear… 不经过模型）；**任务清单**、后台任务、会话恢复 | 终端 UI 和编程专用工具 |

## 现状 → 差距

| 能力 | 现在的桌宠 | 差距 |
| --- | --- | --- |
| 会话 | 聊天记录最多 40 条纯文本，存在 config.json；工具过程只在 TaskLogger 日志里 | 没有可恢复、可分叉、可压缩的会话；崩溃后任务就丢了 |
| 循环 | `AgentController.run()` 一个大函数 | 没有生命周期事件可挂；工具只能串行；结束原因不规范 |
| 扩展 | 本地插件 + stdio MCP | 只能加工具，不能改循环、不能拦截、不能换模型 |
| 钩子 | 无 | 用户没办法“每次执行命令前先过一遍我的脚本” |
| 权限 | 低 / 中 / 高三级 + 确认卡 + 允许的文件夹 | 没有模式（只读计划模式 / 自动允许编辑），没有按工具和参数写的规则 |
| 指令 / 记忆 | 记忆列表全部塞进提示 | 没有分层指令文件，没有技能，记忆不能按需检索 |
| 多智能体 | 无 | 长任务全挤在一个上下文里 |
| 前端 | 桌宠/聊天走 Electron IPC；远程网页靠 `remote-chat/install.py` 给打好的包**打补丁** | 补丁层很脆弱（每次发版都可能对不上），前端之间协议不统一 |
| 后台 | 开发服务器进程管理 | 没有通用的后台任务和定时任务 |
| 模型 | 只支持 OpenAI 兼容接口 | 没有按会话或子智能体选模型，没有用量统计 |

## 方案选择

- **A. 自己演进（推荐）**：参考 dsh 的接缝和事件设计，在现有 `electron/agent/` 上重构出一个轻量的插件运行时，不引入 Cordis。好处：现有的 63 个工具、权限体系、人格、测试都能保住，没有预览版依赖。
- **B. 嵌入 dsh**：把 dsh 当引擎，现有工具改写成 dsh 插件，桌宠作为它的前端。好处：直接接入它的生态。代价：要跟着预览版的不兼容改动走，Windows 工具和人格还是得自己写，权限要重新对一遍。

推荐 **A**，同时在协议层兼容 MCP，以后需要时再兼容 ACP，保留和 dsh、Claude Code 互通的可能。

## “她的身份不变”怎么保证

- **人格插件**：`persona + selfModel` 作为系统提示的第一段，所有面向用户的会话都会带上。子智能体只做内部工作，不带人格；它们的结论由她用自己的口吻转述给用户。
- **形象插件**：订阅运行时事件（思考 / 干活 / 等确认 / 成功 / 失败 / 进度），驱动桌宠的表情、动作和气泡。现在的 `AgentPetSignal` 就是这个东西的雏形。
- **自我记忆**：`selfModel` 继续记录“我做过的事”，数据来源改成会话日志。
- **硬性约束**：任何插件都不能替换人格插件；用户在设置里改性格，仍然是唯一的入口。

## 分阶段计划

每个阶段都能单独发版、单独回滚，测试保持全绿。

### 第 1 阶段：运行时内核（地基）✅
> 实际做法：会话日志目前作为记录和恢复的来源，发给模型的历史仍然来自前端传来的聊天记录（保持和聊天窗口、远程网页的兼容）；改成完全从日志推导，放到第 2 阶段统一协议时一起做。`/compact` 也留到那时。
1. **事件溯源会话**：`session.jsonl`，事件包括 `turn/start|end`、`step/start|end`、`user/message`、`assistant/message`、`tool/call`、`tool/result`、`compaction/*`。模型看到的历史从日志推导出来；现有的 TaskRecap 和压缩改成“视图替换”；崩溃后补一个 `interrupted` 收尾，可以“继续上次的任务”。
2. **回合循环拆成步骤**，并发出生命周期事件：`pre-step`、`request`、`tool:pre`、`tool:post`、`turn-stopping`。规范结束原因：`completed`、`aborted`、`blocked`、`error`、`max-tokens`、`interrupted`。
3. **并行工具**：工具声明 `concurrencySafe(args)`，只读工具并行执行，写操作作为屏障按顺序执行。
4. **斜杠命令**：`/compact`、`/clear`、`/resume`、`/plan`、`/skills`、`/hooks`，直接执行，不经过模型。

### 第 2 阶段：Host 与统一协议（“系统级”的关键）✅
> 实际做法：
> - 没有另起 WebSocket 服务，而是在已有的本地 HTTP 服务（127.0.0.1:17861，长轮询）上扩展：会话、轨迹、命令都放在这里，命令行用本机令牌访问。
> - 会话日志成为对话的唯一来源。
> - remote-chat 已经并进源码，不再需要打补丁。
> - 开机启动沿用原有设置，默认关闭。
> - 聊天窗口改成 harness 式界面。
1. 运行时成为常驻 **Host**：开机自启（可关），桌宠窗口刷新或重载不会打断任务，托盘显示后台任务。
2. **本地 RPC**：只监听 127.0.0.1 上的 WebSocket JSON-RPC，带令牌。桌宠、聊天、远程网页、命令行 `pet` 都走它。
3. **把 remote-chat 正式并入源码**，取消 `install.py` 打补丁这一步。发版从此不再需要“补丁对不对得上”。

### 第 3 阶段：钩子、权限模式、指令和技能 ✅
> 实际做法：
> - 技能（内置 3 个，你也可以自己写，或者让她保存）。
> - 长期守则 AGENTS.md，加上项目里的 AGENTS.md / CLAUDE.md（只作为参考数据）。
> - 权限规则（禁止 + 只对中风险生效的允许）。
> - 钩子（需要批准，改动后要重新批准）。
> - 按相关性挑选记忆。
> - 权限模式在第 2 阶段已经做了。
1. **Hooks**：沿用 Claude Code 的事件名和 JSON 格式（`PreToolUse` 可以返回 allow / deny / ask，`PostToolUse` 可以追加反馈），脚本或插件都能挂。守卫是单调的。
2. **权限模式**：`询问`（默认）、`计划`（只读，先出方案）、`自动允许中风险`。高风险操作永远要确认，不提供“全部跳过”。另外支持规则，例如 `allow: open_url(https://*.bilibili.com/*)`、`deny: run_command(*format*)`。
3. **分层指令**：`她的守则.md`（全局）+ 工作文件夹里的 `AGENTS.md` / `CLAUDE.md`（进入该目录时加载）。
4. **技能**：`skills/<名字>/SKILL.md`，平时只给描述，模型用 `load_skill` 按需展开。
5. **记忆**：按相关性检索，加上“任务记忆”。

### 第 4 阶段：子智能体与后台
1. **子智能体**：`spawn`（全新上下文）和 `fork`（继承当前上下文），可以指定只读工具组和输出 schema，结果交回主会话。
2. **后台任务和定时任务**：例如“每天 9 点汇总评论”“下载文件夹满了提醒我”。无人值守时只做只读操作，需要写入的步骤挂起，等你回来再确认。

### 第 5 阶段：模型与可观测性
1. **模型适配器接缝**：OpenAI 兼容、Anthropic 原生、DeepSeek 思考模式，可以按会话或子智能体选不同模型。`jsonFallback` 改为按模型记住。
2. **用量和费用**：读取每次调用的 `usage`，在设置页显示。会话日志就是审计记录。

## 风险与边界

- **规模**：第 1、2 阶段是大重构，`AgentController`、IPC、remote-chat 都会动。靠现有的 145 个测试和 smoke 守住。
- **安全**：系统级常驻意味着权限更重要。RPC 只监听本机并要求令牌；钩子脚本由用户自己配置，第一次启用时要确认；高风险操作永远逐次确认。
- **dsh 未核实的部分**（权限模式名、沙箱实现、MCP、技能格式）：实施到对应阶段前再读它的 `SAFETY.md`、`compaction.md` 等文档。
